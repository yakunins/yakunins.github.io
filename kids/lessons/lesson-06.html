Theory

Tags, Elements, and Attributes

HTML (HyperText Markup Language) is the standard language every web browser understands. It doesn’t make things look pretty and it doesn’t add interactivity — its only job is to describe the structure and meaning of content on a page.

HTML uses tags to mark up text. A tag is a keyword wrapped in angle brackets, like <p>. Most tags come in pairs: an opening tag (<p>) and a closing tag (</p>). Everything between the opening and closing tag is called an element.

Tags can also carry attributes — extra information tucked inside the opening tag. For example, <a href="https://example.com"> uses the href attribute to tell the browser where a link should go. Attributes always follow the pattern name="value".

Every HTML page shares the same skeleton: a <!DOCTYPE html> declaration at the top, an <html> element wrapping everything, a <head> section for metadata (page title, character set, linked stylesheets), and a <body> section for the visible content. This structure hasn’t changed much since Tim Berners-Lee invented HTML in 1991 at CERN.

Semantic Markup — Why Structure Matters

You could build an entire page using nothing but <div> tags and it would display just fine. So why bother with different tags? Because semantic HTML tells browsers, search engines, and assistive tools what each piece of content actually means.

HTML5 introduced tags that describe their purpose by name: <header> for the top section of a page or article, <nav> for navigation links, <main> for the primary content, <article> for a self-contained piece of writing, <section> for thematic groupings, <aside> for sidebars or related info, and <footer> for the bottom section.

When search-engine crawlers read your page, semantic tags help them understand which text is the main article and which is just navigation. This can improve your site’s ranking in search results — a practice known as SEO. Using <h1> through <h6> for headings (instead of making text big with CSS) creates a clear outline that both humans and machines can follow.

Forms, Links, Images, Lists, and Tables

HTML gives you a toolbox of elements that cover most things you’ll ever need on a web page:

Links use the <a> (anchor) tag with an href attribute pointing to a URL. They are the glue that holds the entire World Wide Web together — without links, there would be no “web” at all.

Images use the self-closing <img> tag with a src attribute for the image path. Lists come in two flavors: <ul> (unordered, with bullet points) and <ol> (ordered, with numbers). Each item goes inside an <li> tag.

Tables use <table>, <tr> (table row), <th> (header cell), and <td> (data cell) to organize information in rows and columns.

Forms let users send data to a server. A <form> wraps input fields like <input>, <textarea>, <select>, and a <button> to submit. Every time you log in, search for something, or fill out a survey, you’re using an HTML form.

Accessibility — Making the Web Work for Everyone

Web accessibility means designing pages so that people with disabilities — visual, auditory, motor, or cognitive — can use them just as easily as anyone else. Roughly 15% of the world’s population lives with some form of disability, so accessible design is not optional; it’s a responsibility.

The simplest accessibility win is the alt attribute on every <img> tag. A screen reader — software used by people who are blind or have low vision — reads the alt text aloud so the user knows what the image shows. If you leave it blank or write something lazy like “image123.jpg,” that person gets no useful information at all.

Heading hierarchy also matters. Screen readers let users jump between headings to navigate a page quickly. If your page skips from <h1> straight to <h4>, the structure feels broken and users may miss important sections. Always use headings in order: <h1> → <h2> → <h3>, and so on.

The WAI-ARIA specification adds extra attributes (like role and aria-label) for cases where plain HTML isn’t descriptive enough. But the golden rule is: use the right semantic HTML element first, and only reach for ARIA when there’s no native tag that does the job. The WCAG guidelines published by the W3C are the global standard for building accessible websites.

Practice Task

Build: “About Me” Page

Create a personal “About Me” page using only HTML (no CSS allowed). The goal is to practice every major HTML element you learned in this lesson — headings, lists, images, tables, and forms — all in one page.

Requirements:

  • A heading hierarchy using <h1>, <h2>, and <h3> — the <h1> should be your name, with sub-sections for hobbies, schedule, and contact
  • An unordered list (<ul>) of at least 5 hobbies or interests
  • An image (<img>) with a meaningful alt attribute describing what the image shows (use any placeholder image URL, e.g., https://placehold.co/300x200)
  • A table (<table>) showing your weekly schedule with columns for day, subject, and time — at least 5 rows of data plus a header row using <th>
  • A contact form (<form>) with: an <input type="text"> for the visitor’s name, an <input type="email"> for their email, a <textarea> for a message, and a submit <button>
  • Use semantic elements: wrap everything in <main>, add a <header> at the top and a <footer> at the bottom with a copyright line
